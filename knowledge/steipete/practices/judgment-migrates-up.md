# Judgment Migrates Up

The skills that make agentic engineering work are the skills of *senior* engineering — not a new discipline. Managing agents resembles managing engineers: delegation, review, and knowing when to intervene. The hard parts stay human: distributed-system design, dependency and platform choices, forward-thinking schemas. "Just because I don't write the code anymore doesn't mean I don't think hard about architecture."

Automating the typing *raises* the bar rather than lowering it — once shipping is cheap, expectations of what you should ship go up. So value migrates from syntax to judgment. At fluency you stop reading most generated code and watch the stream instead, holding the system design in your head (where components live, how data flows) and inspecting only when an agent fails to one-shot something your calibrated sense says should be easy. That failure is a signal, and reading it is the skill (see [[stay-in-the-loop-active-steering]]).

Agents reliably get you ~80% into unfamiliar territory in minutes; a skilled engineer then tests, hunts edge cases, and refactors. This is "rocket fuel" for someone who can spot and fix the slop — and it won't carry someone who can't. The same tool that 10x's an expert leaves a novice shipping confident garbage.

This is the antidote to both hype poles. "AI replaces developers" is wrong because the difficulty doesn't vanish; "AI is only slop" is wrong because a calibrated operator routinely converts that 80% into shipped product. The honest claim is narrower and more useful: agentic coding *relocates* the difficulty up the stack, from how to write it to whether it's right and where it should go.
