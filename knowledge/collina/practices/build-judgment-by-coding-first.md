# Build judgment by coding first

You cannot develop the judgment to review AI-generated code without first
having written code yourself and lived through its failures. Reviewing is a
skill built on having done the work — not a shortcut around it. Recognizing
an inappropriate sorting algorithm, a risky caching trade-off, or a
distributed-systems failure mode requires a mental model that only forms by
making those exact mistakes firsthand; watching an agent produce the answer
doesn't build that model, no matter how many times you watch it.

This reframes what "learning to code" is for. A decade ago you learned to
code because the job was coding. Today the job is judgment, and judgment
requires understanding how software actually works — so fundamentals
(algorithms, distributed systems, hardware, caching, networking) matter more,
not less, precisely because they're what judgment is made of. Skipping them
because "AI handles the coding now" produces developers who can't tell when
the AI is wrong, at the exact moment the ratio of AI-produced code to human
reviewers is exploding.

The practical consequence is a closing on-ramp. The old pipeline —
bootcamp → junior "clock the ticket off" role → learn the rest on the job —
is breaking, because AI now does that junior-level work directly and more
cheaply than training a junior would cost. Internships and senior-pairing
become the substitute apprenticeship: judgment isn't learned from tutorials,
it's learned from watching things break and from working alongside someone
who already has the mental models to internalize. Advice for anyone
starting out: optimize for real exposure to production systems and senior
review, not resume prestige.
