# Manual Testing Techniques

Simon Willison advocates for agents to perform manual testing to verify code works as intended, using various mechanisms depending on the code type.

## Core Principle

Never assume that code generated by an LLM works until that code has been executed. The defining characteristic of coding agents is that they can execute the code they write, but automated tests alone aren't sufficient.

## Testing Mechanisms by Code Type

### Python Libraries
Use `python -c "... code ..."` pattern to pass strings of Python code directly to the interpreter, including code that imports other modules. Agents are familiar with this trick and will sometimes use it without prompting.

### Web APIs  
Exercise APIs using `curl` commands. Telling an agent to "explore" often results in it trying different aspects of a new API, quickly covering substantial ground.

### General Code
For languages without direct execution mechanisms, agents can write demo files to `/tmp` to avoid accidental commits, then compile and run them.

## Browser Automation for Web UIs

Manual testing becomes especially valuable for interactive web UIs. Modern browser automation tools can uncover problems in realistic settings.

### Playwright Integration
Simply telling an agent to "test that with Playwright" may be enough. The agent can select appropriate language bindings or use playwright-cli tool. Playwright offers full-featured APIs with bindings in multiple languages.

### Dedicated CLI Tools
- **agent-browser** by Vercel: Comprehensive CLI wrapper around Playwright designed for coding agents
- **Rodney**: Chrome DevTools Protocol-based tool for direct Chrome control

### Rodney Usage Pattern
Example prompt: "use `uvx rodney --help` to test this, look at screenshots"
- `uvx rodney --help` automatically installs Rodney and provides comprehensive usage information
- Screenshots hint agents to use vision abilities for visual evaluation
- Wide capabilities: JavaScript execution, scrolling, clicking, typing, accessibility tree reading

## Documentation and Work Demonstration

### Showboat Integration
Use Showboat to capture manual testing flows and create documentation artifacts. Key commands:
- `note`: Append Markdown notes to document
- `exec`: Record command, run it, and capture output (prevents cheating)
- `image`: Add images like screenshots to document

The `exec` command is most important as it captures both what the agent did and the actual result, discouraging fabricated outcomes.

## Integration with Automated Testing

Issues found through manual testing should be fixed using red/green TDD to ensure new cases end up covered by permanent automated tests. Agent-maintained browser tests reduce friction of keeping tests current despite design changes.
