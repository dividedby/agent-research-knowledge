# Artifacts — mattpocock

How Matt Pocock's skills/agents are built: structure, conventions, and how the
pieces compose. One concept per file; this index lists them, one line each.

- [skill-anatomy-and-progressive-disclosure](./skill-anatomy-and-progressive-disclosure.md) — a skill is a directory of tiered context: routing description → short body → linked resources, loaded only when needed.
- [buckets-and-promotion-discipline](./buckets-and-promotion-discipline.md) — six lifecycle buckets where the folder mechanically decides whether a skill is advertised in README + plugin.json.
- [setup-seeded-config-and-dependency-tiers](./setup-seeded-config-and-dependency-tiers.md) — a setup skill seeds per-repo config; skills declare hard vs soft dependence on it (ADR 0001).
- [skills-compose-by-handoff](./skills-compose-by-handoff.md) — small skills invoke, hand off to, and share data (the issue tracker) rather than forming one monolith.
- [manual-invocation-control](./manual-invocation-control.md) — `disable-model-invocation` and the description's "Use when" clause govern whether the model may auto-fire a skill.
- [enforced-architecture-vocabulary](./enforced-architecture-vocabulary.md) — a fixed module/interface/depth/seam vocabulary with forbidden substitutes and operational tests (deletion test, etc.).
- [explore-then-confirm-loop](./explore-then-confirm-loop.md) — stateful skills share an explore → present → confirm → write skeleton that defers irreversible writes behind a human checkpoint.
- [out-of-scope-as-design-discipline](./out-of-scope-as-design-discipline.md) — `.out-of-scope/` records deliberate non-features (ADRs for "no"): refuse maintenance surface, prefer natural-language steering over knobs, fix the symptom's real cause.
- [label-driven-agent-ci-pipeline](./label-driven-agent-ci-pipeline.md) — GitHub labels are the state machine; `agent-*.yml` workflows transition/refuse/block, chain phases by label (PAT, not GITHUB_TOKEN), and push-with-lease.
- [structured-output-with-session-retry](./structured-output-with-session-retry.md) — agent↔pipeline seam is one validated `<output>` block; separate work from report, and resume the same session to re-emit on extraction failure without redoing work.
- [sandcastle-plan-execute-merge-loop](./sandcastle-plan-execute-merge-loop.md) — the batch AFK factory: bounded loop of plan → bounded-parallel implement+review in per-branch Docker sandboxes → one merge agent.
- [thin-fail-fast-harness](./thin-fail-fast-harness.md) — a harness owns only what it controls: invert control to the user, refuse to wrap provider interfaces, fail fast over degrade, keep the retry loop in the consumer.
- [triage-state-machine](./triage-state-machine.md) — issue (and opt-in external-PR) workflow as one explicit state machine with category/state role labels, verify-before-grill, grilling as state refinement, refusal with explanation for safety, and a mandatory AI-authorship disclaimer on every tracker write.
- [stateful-teaching-workspace](./stateful-teaching-workspace.md) — file-backed learning workspace with mission grounding, progressive glossary building, and zone-of-proximal-development calculation from learning records.
- [production-automation-workflows](./production-automation-workflows.md) — production deployment through third-party service integration chains that coordinate file sync, webhooks, and content scheduling.
- [completion-signal-and-hanging-process-handling](./completion-signal-and-hanging-process-handling.md) — two-phase timeout strategy differentiating stuck agents from completed work with hanging subprocesses; completion signal switches from idle timeout (failure) to grace timeout (success with warning).
- [per-step-timeout-architecture](./per-step-timeout-architecture.md) — individual timeouts for every lifecycle step (container, git, hooks) with dedicated error types carrying operational context, preventing any single operation from hanging the workflow.
- [filesystem-backed-session-requirement](./filesystem-backed-session-requirement.md) — resumable sessions only supported for agents storing conversation state as discrete files, not databases; prioritizes opaque file transfer over schema coupling.
- [isolated-sandbox-sync-tracking](./isolated-sandbox-sync-tracking.md) — sandbox-owned refs track patch base for git format-patch/am cycles, solving SHA rewrite coordination between sandbox and host without exposing infrastructure refs to user.
- [context-compression-and-handoff-mechanics](./context-compression-and-handoff-mechanics.md) — split concerns across independent agent sessions through context compression; enables focused work without losing critical information while addressing smart zone limitations — and why handoffs are structurally lossy (primary vs secondary source).
- [ralph-loop-implementation-patterns](./ralph-loop-implementation-patterns.md) — autonomous agent execution through simple bash loop patterns; adapts for different task sources and output formats while maintaining fresh context windows.
- [skill-distribution-via-npm-postinstall](./skill-distribution-via-npm-postinstall.md) — ship shared skills as a versioned npm package whose postinstall symlinks them into `.claude/skills`, reusing npm's versioning instead of a bespoke sync tool.
- [afk-mediated-approval-middle-ground](./afk-mediated-approval-middle-ground.md) — `permissionMode`/`approvalsReviewer` let an AI adjudicate each tool approval — a third option between full bypass and asking a human for AFK host runs.
- [session-fork-for-fanout](./session-fork-for-fanout.md) — `RunResult.fork()` continues a session under a new id for fan-out, isolating only the conversation; the caller must give each child its own branch.
- [broken-until-configured-scaffold](./broken-until-configured-scaffold.md) — init can scaffold a deliberately broken project with a single fail-fast sentinel + a setup prompt the user's agent runs, rather than a wrong-but-running default.
- [filtered-list-as-ground-truth](./filtered-list-as-ground-truth.md) — prompt hardening so an empty pre-filtered task list reads as "done", not as a stale snapshot the agent should re-query unfiltered.
- [prompt-templating-data-code-boundary](./prompt-templating-data-code-boundary.md) — only author-written shell blocks execute; substituted arg values are inert data via a provenance marker (forgeries stripped), making forwarded untrusted content injection-safe.
- [procedures-vs-abilities](./procedures-vs-abilities.md) — skills split into two sub-types by what they encode: a procedure is a fixed step sequence (`/grill-me`), an ability is a judgement-applied competence (`/tdd`); the split tells the author whether to write a recipe or install a habit.
- [invocation-axis-user-vs-model](./invocation-axis-user-vs-model.md) — the whole collection sorts on one axis: user-invoked orchestrators (`disable-model-invocation`, human-only, zero context load) vs model-invoked reusable discipline; a user-invoked skill may invoke model-invoked ones but never another user-invoked one, and `ask-matt` routes over them.
- [codebase-design-deep-module-vocabulary](./codebase-design-deep-module-vocabulary.md) — the deep-module vocabulary extracted into a standalone shared skill, plus DEEPENING (dependency-category → test strategy) and DESIGN-IT-TWICE (parallel sub-agents each given a different design constraint).
- [domain-modeling-active-discipline](./domain-modeling-active-discipline.md) — the active build-the-glossary skill (challenge/sharpen/scenario/cross-reference/update inline), CONTEXT.md as glossary-only, and the three-part ADR gate; distinct from merely reading CONTEXT.md.
- [writing-great-skills-vocabulary](./writing-great-skills-vocabulary.md) — skill authoring as wrangling predictability: context vs cognitive load, context-pointer wording, the information hierarchy, completion criteria, leading words, and the named failure modes (premature completion, duplication, sediment, sprawl, no-op) — with the context-relative no-op + deletion test, the no-op pass, authoring-by-hand, and its own graduation into `writing-for-agents`, the same levers applied to any agent-facing document.
- [resolving-merge-conflicts-by-intent](./resolving-merge-conflicts-by-intent.md) — resolve conflicts by recovering each side's original intent from commits/PRs/issues, preserve both where possible, never invent behaviour, never `--abort`, then let automated checks confirm.
- [skills-need-token-free-import](./skills-need-token-free-import.md) — the standing wishlist: skills should import each other as a flat set of modules via a harness-agnostic syntax the harness resolves to a path link, without paying description context-load; submodules/`references/` copy/isolated-context routing all rejected.
- [display-as-swappable-rendering-backend](./display-as-swappable-rendering-backend.md) — all run output goes through one tagged `Display` service with three swappable layers (Clack/File/Silent); `text` (line) vs `textChunk` (raw stream fragment) is a first-class split, with `midLine` tracking + buffer-flush keeping structured entries off the tail of streamed prose.
- [wizard-skill-for-manual-procedures](./wizard-skill-for-manual-procedures.md) — generates a bash script that walks a human through a manual third-party-setup/migration procedure; a shared, never-hand-edited library owns the UX, the author only scopes and writes stages.
- [review-skill-two-axis-with-smell-baseline](./review-skill-two-axis-with-smell-baseline.md) — `code-review` (shipped, renamed from `review`) runs Standards vs Spec as two parallel sub-agents whose findings are never merged; Standards carries a fixed Fowler smell baseline that a documented repo standard always overrides; it's now the final gate of the main build chain.
- [docs-page-mirrors-promoted-skills](./docs-page-mirrors-promoted-skills.md) — every promoted skill gets a paired human-facing docs page published at `aihero.dev/skills-<name>`, kept in sync with the `SKILL.md` as a maintenance obligation, not a one-time export.
- [self-throttling-generator-pipeline](./self-throttling-generator-pipeline.md) — a cron-triggered agent that proposes new work (PRDs, issues) gates itself on the count of its own still-open output before adding more, rather than running unbounded.
- [agent-facing-cli-as-glossary-surface](./agent-facing-cli-as-glossary-surface.md) — a read-only CLI's `--help` text can teach the same domain vocabulary as `CONTEXT.md`, reusing existing read services, at the cost of a manual two-artifact sync obligation.
- [sandbox-exec-for-verification-gates](./sandbox-exec-for-verification-gates.md) — `sandbox.exec()` runs a raw shell command in the same warm container an agent turn just ran in, so a verification gate (tests, lint, a custom check) doesn't need to reach past the harness into the provider or pay for a fresh container.
- [prototype-answer-is-the-artifact](./prototype-answer-is-the-artifact.md) — `/prototype` builds disposable code to answer one design question (a shareable clickable-HTML logic branch, non-developer-drivable, vs a UI branch); the verdict is captured durably, sometimes inlined into `to-spec`'s template, and the code is kept as a primary source on a throwaway branch, never hardened.
- [research-as-delegated-background-reading](./research-as-delegated-background-reading.md) — `/research` runs as a background agent, investigating primary sources and leaving a single cited Markdown file that feeds the main flow rather than deciding anything itself.
- [recency-biased-scope-selection](./recency-biased-scope-selection.md) — scan recent commit history to find hot spots and scope an open-ended codebase review there first, applying YAGNI to *where you look*, not just what you build.
- [two-distribution-philosophies-fork-vs-subscribe](./two-distribution-philosophies-fork-vs-subscribe.md) — skills.sh copies skills into a repo to hack on (fork); the Claude Code plugin installs the same promoted set as a read-only, always-current bundle (subscribe) — same content, opposite ownership models, both offered on purpose.
- [questionnaire-grills-the-send-not-the-subject](./questionnaire-grills-the-send-not-the-subject.md) — `to-questionnaire` interviews the user only about who it's for and what they need back, then writes questions aimed at the gap between what the recipient knows and what the user needs — for decisions the user can't answer alone.
- [attachable-files-as-opt-in-agent-context](./attachable-files-as-opt-in-agent-context.md) — freeform files attach to the entity an agent-writer already reads; the context picker defaults on for cheap text-like extensions, off for the rest, and routes images around the checkbox entirely.
- [cli-for-agent-live-view-for-human](./cli-for-agent-live-view-for-human.md) — for non-coding work, split the interface: a CLI gives the agent full write control, a custom live-reloading view gives the human comfortable read access, with a "copy link" URI closing the loop back to the agent.
- [deterministic-first-agent-escalation](./deterministic-first-agent-escalation.md) — try the deterministic tool first, call the agent only for the residual, then verify its result on disk rather than trusting its report — four gates, only one calls an LLM.
- [context-sources-ranked-by-fidelity](./context-sources-ranked-by-fidelity.md) — a generative writer's several context sources are ranked on an explicit fidelity ladder (plan → script → what was actually said), with supporting material excluded from the ladder as evidence-only, never a source of claims.
- [single-computation-backs-every-consumer](./single-computation-backs-every-consumer.md) — when a blocking gate, a UI warning list, and an agent-facing CLI verb all answer the same "is this ready" question, compute it once and let every surface read that one result, so a human and an agent can never be told different answers.
- [extending-an-agent-cli-to-remote-machines](./extending-an-agent-cli-to-remote-machines.md) — a CLI reachable from a remote agent box authenticates with a bearer token over the one transport the author also uses, refuses local-only commands up front by name rather than failing mid-work, and refuses a schema-version mismatch outright instead of tolerating it.
- [router-skill-hand-maintained-map-drifts](./router-skill-hand-maintained-map-drifts.md) — `ask-matt` is a secondary source over the skills it routes to (a hand-written map, not a live scan), so it goes stale, reports installed skills as missing, and asserts wrong behaviour from its own gloss instead of the skill's file — verify a load-bearing claim by having it open the file.
- [implement-trusts-upstream-without-reverifying](./implement-trusts-upstream-without-reverifying.md) — `implement` never reopens the plan it's handed and never re-validates it either, so a malformed ticket (unagreed seams, bad slicing) builds exactly as written; it also has no completion step and no notion of a concurrent session sharing the same working tree.
- [cache-derived-data-by-content-hash](./cache-derived-data-by-content-hash.md) — key an expensive derived-data cache on a hash of the source file's content, not its path or mtime, so re-recording transparently invalidates it and an untouched file transparently reuses it; chunk large inputs at silence, not byte offsets.
- [em-dash-ban-rewrite-not-substitute](./em-dash-ban-rewrite-not-substitute.md) — a repo-wide ban on em-dashes (an AI-prose tell) is enforced by rewriting each sentence for the punctuation it actually needs, never by a blind find-and-replace.
- [frontier-parallel-implementers-in-worktrees](./frontier-parallel-implementers-in-worktrees.md) — `implement-spec` works a spec's tickets as a task graph, fanning one implementer subagent per ready-frontier ticket into its own worktree/branch, merging incrementally and re-evaluating the frontier after each merge, with sparse context-pointer communication and a shared exploration subagent's notes.
- [retro-skill-symptom-to-intervention-checklist](./retro-skill-symptom-to-intervention-checklist.md) — `retro` (STUB) bounds session self-improvement to seven fixed symptom→intervention categories (navigation, checks, standards, AGENTS.md, tool economy, no-ops, information access), routing standards fixes to review rather than implementation.
