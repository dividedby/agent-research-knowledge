# Software engineering vs development distinction

Geoff Huntley draws a critical distinction between software development (which is being commoditized) and software engineering (which remains essential). This separation defines how professionals should adapt to AI-driven changes in the industry.

## The fundamental split

**Software Development** (being commoditized):
- Typing code and prompting LLMs
- Manual coding and implementation
- Anyone can now be a "developer" using tools like Cursor
- "A hairdresser using Cursor" can perform development tasks
- Knowledge and skill have been commoditized

**Software Engineering** (remains essential):
- Acting as "locomotive engineers"—keeping the train on tracks
- Designing safe, reliable systems and automations
- Working "on" the business rather than "in" the business
- Focus on loops, automations, safety mechanisms
- Risk engineering and responsible AI utilization

## The new software engineer role

Software engineers now function like locomotive engineers:
- Monitor and guide automated systems
- Design safety mechanisms (sandboxing, credential management, security)
- Create risk engineering frameworks
- Ensure responsible AI utilization
- Focus on system reliability over manual implementation

"Engineers now act like locomotive engineers—keeping the 'train' on tracks by designing safe, reliable systems/automations rather than working 'in' the business (manual coding)."

## Economic transformation

The unit economics of software have fundamentally changed:
- Software development now costs $10.42/hour (less than minimum wage)
- "Software can now be developed cheaper than the wage of a burger flipper"
- Anyone can become a software developer through AI tools
- Model-first companies operate as "lean, apex predators"

## Identity crisis and adaptation

For professionals whose identity is tied to traditional development:
- "If your identity is tied to being a traditional 'software developer' (keyboard typing), it's a tough time"
- Must shift focus to engineering discipline and systems thinking
- Need to embrace automation and AI augmentation
- Risk "employment suicide" by avoiding AI tools

## Professional survival strategies

**Immediate actions:**
- If employer bans AI tools, "leave immediately"
- Prioritize raw technical and cognitive skills
- Engineer away concerns through systematic approaches
- Replace manual processes with automated, risk-based systems

**Skill evolution:**
- Move from binary code reviews to risk-based approaches
- Implement feature flags and constrained blast radius
- Design auto-migrations and system reliability
- Focus on cognitive and architectural thinking

## The abundance era implications

Traditional software scarcity (differentiated libraries, hard-to-replicate tech) gives way to abundance:
- Easy generation and reimplementation of functionality
- Software products become hyper-commodity utilities
- Vendor lock-in and switching costs vanish
- Auto-migration of databases and applications becomes trivial

True competitive moats now exist in non-technical areas:
- Contracts and relationships
- Distribution networks
- Business judgment and taste
- "The hard things of business"

## Open source transformation

Traditional open source rationale disappears:
- Libraries existed to ease hiring and share reusable code
- AI generation eliminates need for external dependencies
- Benefits of first-party code: faster evolution, full control, no supply chain attacks
- Avoids maintainer burnout, GitHub delays, abandoned projects

"Better to generate first-party code for faster evolution, full control, and no human 'tool calls' (which disqualifies true AGI-like autonomy)."

## Future outlook

The transformation enables hyper-personalized software where old models of building and scaling through scarcity are disrupted. Success requires:
- Running fast and staying curious
- Adapting to the "brave new world"
- Embracing abundance rather than fighting scarcity mindset
- Building systems that leverage rather than resist AI capabilities
